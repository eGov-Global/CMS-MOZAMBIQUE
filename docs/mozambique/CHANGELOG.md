# Changelog — DIGIT Complaint Management System, Mozambique

All notable changes to the Mozambique distribution of the DIGIT Citizen Complaint Resolution System (CCRS) are recorded here.

The format is adapted from [Keep a Changelog](https://keepachangelog.com/); versioning follows the upstream policy in `docs/rapid-release-approach.md` §4 (SemVer `vMAJOR.MINOR.PATCH`; tags are immutable and are the unit of deployment). Because this distribution is a *customization* of an upstream product rather than a greenfield codebase, the sections below explicitly separate what came from upstream, what Mozambique added, and what Mozambique changed.

- Product repository: `eGov-Global/CMS-MOZAMBIQUE`
- Upstream product repository: `egovernments/Citizen-Complaint-Resolution-System`

### Upstream CCRS functionality (retained, unchanged)

Everything below is inherited from upstream at `815b2374` and is **not** modified by the Mozambique line. It is listed so an engineer knows where *not* to look for Mozambique-specific behaviour.

- **Platform services.** Only ~7 first-party backend services exist in-tree: `pgr-services`, `digit-config-service`, `novu-bridge`, `novu-bridge-endpoint`, `novu-dashboard`, `digit-user-preferences-service`, `xstate-chatbot`, plus `utilities/default-data-handler`, `utilities/otp-publisher`, `digit-mcp` and `turbopass/search-api`. **All other DIGIT services (egov-user, egov-workflow-v2, egov-mdms-service, egov-localization, egov-filestore, egov-hrms, …) are prebuilt `egovio/*` images with no source in this repository** and are consumed unchanged.
- **Runtime stack.** Java 17 / Spring Boot 3.2.2 for in-tree Java services (`pgr-services` 3.0.0). Kong API gateway, Gatus health checks — all unmodified.
- **PGR core domain.** Complaint create/search/update contracts, the persister/indexer topology, workflow engine integration (`egov-workflow-v2`), encryption/decryption service integration and the notification engine are upstream code; Mozambique extends them at defined seams rather than replacing them.
- **CI, Helm charts, gateway config.** `.github/` workflows and parity scripts, `devops/` (Helm / deploy-as-code charts), the top-level `ansible/` tree, the root `docker-compose.egov-digit.yaml` and `local-setup/kong/kong.yml` are **byte-identical to `815b2374`**. There are zero Mozambique CI changes, zero Kubernetes/Helm changes and zero Kong route changes on this line.
- **Legacy frontends.** `digit-ui-v2` and `frontend/micro-ui` remain in-tree but are **not deployed** by this product. The deployed frontend is `digit-ui-esbuild` (esbuild React 17 SPA, served at `/digit-ui`); `configurator` (DIGIT Studio) is additionally deployed for Mozambique.
- **The standard single-tier PGR workflow** (`utilities/default-data-handler/src/main/resources/PgrWorkflowConfig.json`, the GRO/LME municipal grievance flow) is retained unchanged alongside the new CMS variant, so an upstream-style deployment built from this tree still works.

### Mozambique-specific additions

#### Access control, confidentiality and search (backend, `pgr-services`)

- **Employee department-scoped complaint search (opt-in ABAC).** New `EmployeeDepartmentScopeService`, invoked from `_search`, `_count` and `_plainsearch` via `PGRService#applyEmployeeDepartmentScope`. For callers holding a role listed in the new `pgr.department.scope.roles` property, the caller's **current** HRMS assignment department(s) (`isCurrentAssignment == true` only, so ended assignments cannot widen access) are resolved and injected as a `ser.additionaldetails->>'department' IN (...)` predicate. **Fails closed** — an HRMS outage yields an empty result set and `count = 0` rather than everything. `departmentCodes` is `@JsonIgnore`, i.e. server-resolved only and never bindable from a request body. Ships with the property **empty**, so upgrading changes nothing until an operator opts in.
  `backend/pgr-services/.../service/EmployeeDepartmentScopeService.java`, `.../repository/rowmapper/PGRQueryBuilder.java`, `.../resources/application.properties`
- **New endpoint `POST /pgr-services/v2/request/_admin/_search`.** Cross-department administrative complaint search returning page rows *and* `totalCount` in one response (previously `_search` and `_count` had to be called separately). Criteria: `tenantId` (mandatory, else `INVALID_SEARCH`), `serviceRequestId`, `departmentCode` set, `fromDate`/`toDate`, `limit`/`offset` (default 20, hard max 50), `sortBy`/`sortOrder`. Departments are resolved in **both** directions (code→name and name→code) so either stored form matches. **See Known Limitations #1 — this endpoint has no server-side authorization gate.**
  `.../web/controllers/AdminComplaintSearchController.java`, `.../service/AdminComplaintSearchService.java`, `.../web/models/AdminSearchCriteria.java`, `.../web/models/AdminSearchResponse.java`
- **Selective field visibility for confidential complaints (`x-no-mask`).** Confidential complaints were previously masked all-or-nothing, which hid the very fields staff need to triage the case (the institution being complained about). `ComplaintTemplateTypeConfig` now carries `noMaskFields`, parsed from an MDMS `x-no-mask` schema directive per `caseRelatedTo`; `EncryptionDecryptionService#maskAll(ext, cfg)` decrypts first and then masks everything *except* the exempt fields. A new `maskAllPlaintext(ext, cfg)` overload is used on the update path, where values are already plaintext, so no decrypt is attempted on cleartext. `cfg == null` still degrades to full masking. Seeds exempt `instituteName` (IGE) and `entityName` + `entityAddress` (IGSAE).
  `.../service/EncryptionDecryptionService.java`, `.../util/MDMSUtils.java`, `docs/migration/seed/ComplaintExtendedAttributeSchema.json`
- **`createdBy` search filter.** A `CMS_RECEPTION_OFFICER` files complaints on a citizen's behalf and is neither the account holder nor ever the assignee, so their inbox was empty. `RequestSearchCriteria` gains `Set<String> createdBy` (`ser.createdby IN (...)`, added to the *shared* WHERE builder so list, count and pagination stay consistent). Department scoping is deliberately skipped when `createdBy` is set, so "complaints I filed" is never silently narrowed by the caller's own department. Previously an unknown `createdBy` parameter was silently ignored — a bogus UUID returned the identical result set. (CCSD-2135)
- **`department` query parameter** on the existing `_search`/`_count` contract (client-bindable `@SafeHtml String`, distinct from the server-resolved ABAC set), and a **`lastModifiedTime` sort option** on the shared query builder — both additive to the existing contract.
- **Shared department-lookup infrastructure.** `MDMSUtils#getDepartmentCodeToNameMap(tenantId)` reads `$.MdmsRes.common-masters.Department[*]`, tries the city tenant first and falls back to state, and caches per city tenant in a `ConcurrentHashMap` that **never caches an empty result** (so a transient MDMS failure cannot poison the cache). `HRMSUtil#getCurrentDepartment` adds current-assignment resolution.

#### CMS multi-tier workflow (master data)

- **New `CmsPgrWorkflowConfig.json`** (367 lines, 11 states / 18 actions, tenant templated as `{tenantid}`) implementing the Mozambican inspectorate's 4-desk chain instead of DIGIT's single-tier municipal flow: `APPLY` (CITIZEN | CMS_RECEPTION_OFFICER) → `PENDINGFORASSIGNMENT` → `ASSIGN` by `CMS_SCREENING_OFFICER` → `REFERRED` → `ASSIGN` by `CMS_SUPERVISOR` → `INVESTIGATION` → `RESOLVE` / `REJECT` / `AWAITINGINFORMATION` by `CMS_CASE_MANAGER`. `REASSIGN` exists only at `REFERRED` and lands on `PENDINGFORREASSIGNMENT`, which returns to the screening officer. Terminal states: `REJECTED`, `RESOLVED`, `CLOSEDAFTERREJECTION`, `CLOSEDAFTERRESOLUTION`, `CANCELLED`. `businessService` remains `"PGR"`, so the whole platform integration surface is unchanged.
  `utilities/default-data-handler/src/main/resources/CmsPgrWorkflowConfig.json`
- **`pgr.workflow.variant` deploy switch.** `DataHandlerService` gains `@Value("${pgr.workflow.variant:standard}")`, selecting `CmsPgrWorkflowConfig.json` when the value is `cms`. One image serves both the Indian and the Mozambican deployment without forking the seeder. **See Known Limitations #7 — nothing in the tree currently sets this variable.**
- **Asymmetric reopen routing.** `REJECTED.REOPEN → REFERRED` (skips re-screening; the supervisor is already seized of the case) while `RESOLVED.REOPEN → PENDINGFORASSIGNMENT` (restarts screening). Deliberate, per the commit body.

#### Roles, grants and localization (master data)

- **13 new role codes** implementing the PRD's 4-dimension authorization model (base + functional + scope + permission): `CMS_RECEPTION_OFFICER`, `CMS_SCREENING_OFFICER`, `CMS_SUPERVISOR`, `CMS_CASE_MANAGER`, `CMS_ADMIN`, `CMS_DASHBOARD_VIEWER`, `CMS_VIEWER`, `CONFIDENTIAL_COMPLAINT_VIEWER`, `CENTRAL_USER`, `DEPARTMENT_USER`, `COMPLAINTS_VIEWER`, `COMPLAINTS_EDITOR`, `COMPLAINTS_CREATOR`, `DGRO` — so a persona can be re-scoped or temporarily stripped of edit rights without changing their job role. Without these, employee onboarding fails with "Role not valid" on a fresh environment.
  `.../mdmsData/ACCESSCONTROL-ROLE/ACCESSCONTROL-ROLES.roles.json`
- **335 new role→action grants** (roleactions 396 → 731 rows across 29 role codes; 0 removed). `CMS_VIEWER`, `CMS_SUPERVISOR` and `CMS_CASE_MANAGER` each receive exactly GRO's 37-action set (verified set-equality). `CMS_RECEPTION_OFFICER` = GRO minus the 5 PGR-report actions, plus the "Create Complaint" menu. Read-only tiers (`CMS_ADMIN` 22, `CMS_DASHBOARD_VIEWER` 24, `COMPLAINTS_VIEWER` 24, `CENTRAL_USER` 22, `DEPARTMENT_USER` 22) all omit `/egov-wf/process/_transition` and PGR `_create`/`_update`. `CONFIDENTIAL_COMPLAINT_VIEWER` is a deliberately minimal 16-action set intended to be stacked on another role.
- **Portuguese (pt_PT) localization packs.** `localisations/pt_PT/rainmaker-pgr.json` (283 messages) and `localisations/pt_PT/rainmaker-common.json` (61 messages); `default.localization.locale.list` becomes `en_IN,hi_IN,pt_PT` so the data handler registers the locale for every new tenant. Delivered three ways: data-handler classpath load on tenant creation, the migration runner's `landing` phase, and the standalone `seed-landing-config.sh`. **Coverage is deliberately partial — see Known Limitations.** (CCSD-1987, CCSD-2067/2068/2076/2083)
- **CMS workflow state/action labels** in EN and pt_PT: `CS_COMMON_PGR_STATE_REFERRED` ("Referred to department" / "Encaminhada"), `_INVESTIGATION` ("Under investigation" / "Em Investigação"), `_INFOFROMCITIZEN` ("Awaiting information from citizen" / "Aguarda Informação do Cidadão"), plus 22 `CS_ACTION_*` labels. Without these the CMS states rendered as raw keys on pilot and production.
- **"Fala Cidadão" rebrand.** 13 product-name keys across four packs now read *Fala Cidadão* instead of *Citizen Complaint Resolution System*; +299 `en_IN` PGR keys, +20 `en_IN` common, +66 `default` PGR. New key families: `PGR_CHANNEL_*` (channel of receipt), rewritten `CS_REOPEN_OPTION_*`, `CS_DESC_MIN_CHARS`, `ROWS_PER_PAGE`, `ENGLISH`/`PORTUGUESE` language-picker labels.

#### Citizen-facing features (`digit-ui-esbuild/products/pgr`)

- **Citizen authority dispatcher + per-category dynamic fields.** One citizen portal fronts several inspection authorities (IGE, IGSAE). The citizen first picks "what the complaint is about"; that pick sets `resolvedTenantId`, which then drives complaint-catalogue lookup, the boundary tree, map config and the filestore tenant for uploads. Switching authority resets complaint type, boundary and uploaded photos (filestore ids are tenant-scoped). Per-authority fields are generated from a draft-07 JSON Schema (`x-order` / `x-widget` / `x-label-key` / `x-security`) and submitted flat at the new top-level `service.extendedAttributes`. **Single-authority deployments auto-select the only row and never render the picker.**
  `.../pages/citizen/Create/CreatePGRFlowV2.tsx`, `.../utils/extendedAttributes.js`
- **Public config-driven landing page + in-app Privacy Policy.** ~30 new files under `.../pages/citizen/Landing/`: a section registry driven by MDMS `RAINMAKER-PGR.LandingSection` / `LandingPageConfig` (state tenant with city overlay), a built-in `DEFAULT_LANDING_CONFIG` so the page never renders blank, a PT/EN copy deck overridable by `PGR_LANDING_*` localization keys, `--pgrl-*-brand` design tokens, a preview bridge so the Configurator Builder shows live edits, and section components (Hero, Channels incl. Linha Verde, HowItWorks, Institutions, News, Types, Privacy, FinalCta, Footer). (CCSD-2004/2006/2009)
- **Shared file-upload component (`PgrFileUpload`, 420 lines)** wired into *every* PGR surface — citizen create step 3, citizen reopen, the employee create form, and every workflow action modal. Drag-and-drop, preview cards with image thumbs / doc icons / inline video+audio players, per-file remove, 5 MB per file, keyboard accessible, uploads to an explicitly passed tenant. Previously: citizen create was image-only, citizen reopen was image-only with a 2 MB cap, the employee form had **no** uploader at all, and workflow actions offered an upload only when the target state was flagged `docUploadRequired`.
- **Video/audio attachment playback.** New `utils/attachmentKind.js` centralises classification (strips the S3 presign query before reading the extension; treats a multi-URL variant list as a positive image signal, since the filestore only generates variants for images). Attachments split into images (lightbox), media (real `<video>`/`<audio>` with `preload=metadata`, first-frame poster) and docs (download chips), with a per-element `error`-event fallback rather than a codec allowlist. (CCSD-2027, CCSD-2153)
- **Per-step timeline attachments with PII masking rules.** Attachments are resolved once per workflow load, grouped by each process instance's `tenantId`, and rendered per step so the full history is visible. Masking: a **citizen** actor's name and number are always fully masked to `******`; `maskEmployeeContacts` masks non-citizen actors on the employee page; `hideEmployeeContacts` omits employee identity lines entirely on the citizen page; a backend-masked mobile also forces the name to be masked.
- **Confidential complaints + "Complainant Details" card** on the employee details page, rendered only when the complaint was filed on someone's behalf (`auditDetails.createdBy != citizen uuid`). When `isConfidential` is set, name, mobile and correspondence address are replaced with the backend `****` sentinel. An "Additional Details" card renders `extendedAttributes` as ordered rows.
- **Cross-department Admin Complaint Search page** (811 lines) at `/employee/pgr/admin-search`: complaint-number filter with recent suggestions, department multi-select with in-field chips and a "No department (N/A)" sentinel, range calendar, server-side sortable table, status pills, pagination and Excel export.
- **Testing-tenant scoping (`isTestingTenant`).** A shared rule — tenant codes flagged `isTestingTenant` in the `tenant.tenants` master, unioned with the legacy `TESTING_TENANT_ID`, crossed with the per-entrance `TESTING_MODE` boolean — decides visibility in four places: the citizen authority dispatcher, the citizen complaints list, the employee login city dropdown, and forgot-password. Production entrances hide testing tenants; the testing entrance shows only them.
- **Employee create-complaint enrichment:** channel-of-receipt chip radiogroup (In Person / Email / Letter / Linha Verde) riding `service.source`, complainant address, real map coordinates, schema-driven dynamic fields, an `isConfidential` checkbox and attachments.
- **History-derived assignee routing** (`utils/workflowAssignee.js`): walks `/egov-wf/process/_search?history=true` at the **complaint's** tenant and returns the most recent participant holding a given role, so a citizen reopening a complaint lands back on the Supervisor who handled it and a rating is attributed to the Case Manager — without asking the citizen to pick a person. A no-op on the standard PGR workflow, whose history never contains `CMS_*` roles. (CCSD-2167)

### Mozambique-specific modifications of upstream behaviour

- **Workflow action modal is now fully workflow-driven.** Upstream `PGRDetails.js` held a static `ACTION_CONFIGS` array, so any action not in that list rendered no modal form — which made every CMS action unusable. `buildActionFormConfig()` now generates the modal from BusinessService metadata: assignee picker only when the target state is non-terminal and has assignable roles (never for `REJECT` or `AWAITINGINFORMATION`), attachment uploader on every action (mandatory only when the target state sets `docUploadRequired`), always-mandatory comments. `AssigneeComponent` renders an explicit "no eligible employee" error instead of a silently empty dropdown. (CCSD-2124, CCSD-2081)
- **Terminal transitions may now carry an assignee.** `WorkflowService#isTargetStateTerminal(businessService, currentStatus, action)` inspects the BusinessService definition (matching the current state by `applicationStatus` **or** state name), and when the target state is terminal it withholds the assignee list from `egov-workflow-v2` — which rejects any assignee for a state that defines no actions — while **deliberately leaving it on `request.getWorkflow()`** so the notification path and Kafka payload still resolve the intended person. Unknown state/action returns `false`, so the engine remains the authority for every non-terminal transition. (CCSD-2167)
- **Notification department resolution rewritten** to a 3-tier fallback: (1) `ComplaintHierarchy` mapping for the `serviceCode`, (2) the department already stored on the complaint (`additionalDetails.department`, treating `"NA"`/blank as absent), (3) the assignee's own current HRMS department. Localization is attempted with `COMMON_MASTERS_DEPARTMENT_<value>` and falls back to the raw value when the key is unseeded. Upstream threw `JSONPATH_ERROR`/`PARSING_ERROR` outright when the department could not be read, and could throw `IndexOutOfBoundsException` on empty designation/name lists.
- **Citizen complaint details rebuilt on the workflow timeline.** Upstream used a status-ordered component driven by a hardcoded status list, so CMS states did not render at all. The page now fetches process instances directly and renders the same `TimelineWrapper` the employee side uses, so *any* BusinessService renders. Citizen actions are derived from the current state's `nextActions` filtered to the CITIZEN role (`COMMENT` excluded; `REOPEN` gated on the `ComplainClosingTime` idle window). The complaint hierarchy is fetched at the **complaint's** tenant, and the definition that owns the complaint's leaf is selected — a state root can aggregate several authorities' hierarchies.
- **Citizen create wizard reduced from 5 steps to 3** (complaint / where / details) with a numbered progress bar, hint banners and inline spinners instead of a blank full-page spinner, plus a `catalogueLoadedFor` guard so a stale tenant's catalogue is never shown. Validation hardened: description 20–1000 characters **and** at least 3 Unicode letters (upstream accepted `00000000000000000000`); optional e-mail must be well-formed; both consent checkboxes (TRUTHFULNESS, DATA_PROCESSING) are mandatory. (CCSD-1952/1955/1956/1978/1979/1980/2072)
- **Citizen reopen preserves routing data.** New `utils/additionalDetail.js` (`readAdditionalDetailObject`, `mergeAdditionalDetail`) replaces the previous behaviour, where REOPEN and RATE **overwrote `service.additionalDetail` wholesale** — wiping the `department`/`serviceName`/`supervisor` keys that department-scoped supervisors depend on, so reopened complaints vanished from their inbox. REOPEN additionally resets escalation bookkeeping on purpose (a reopen starts a fresh lifecycle); RATE now stores feedback under a `ratingFeedback` key instead of stringifying over the object.
- **Reception-officer inbox defaults.** When `CMS_RECEPTION_OFFICER` is the user's sole CMS role, the inbox adds `createdBy = own uuid` as a **server-side** filter, so pagination and count stay correct. The default tab moves from "assigned to me" to "ALL", and `OPEN_STATES` becomes the union of standard-PGR and CMS non-terminal states (`REFERRED`, `INVESTIGATION`, `INFOFROMCITIZEN`, plus the `applicationStatus` spellings `REASSIGND` and `AWAITINGINFORMATION`).
- **Localization now merges a city-tenant overlay.** `getLocale` fetches each module at the state tenant **and** the current city tenant in parallel and merges with the city copy winning per code, with a back-fill pass for modules cached before a city tenant was known. Complaint-hierarchy names, department names and boundary headings are seeded at the city tenant and previously rendered as raw codes. Boundary labels are loaded at the tree's tenant and injected via `i18next.addResources`. (CCSD-2161)
- **Default-language bootstrap.** `StoreService` falls back to `Digit.Utils.getDefaultLanguage()` instead of `languages[0]`, so a fresh session renders pt_PT rather than English (English happened to be first in the `StateInfo` seed).
- **MDMS v2 calls can target a tenant.** `useCustomMDMS`'s v2 branch previously hardcoded `MdmsCriteria.tenantId` to the current tenant and **ignored the positional `tenantId` argument**, and the cache key had no tenant dimension. Callers can now pass `mdmsv2.tenantId`, which also enters the query name so the cache key is tenant-scoped. `useCustomAPIHook` gains an opt-in `idbTtlSecs` persisting responses to IndexedDB (1-day TTL for the v2 MDMS path).
- **Boundary cascade behaviour changed for employees** — see *Functionality removed/disabled*. Additionally: a childless node is now unconditionally a leaf (Mozambique's tree is uneven — some Distritos have no Municipio, and the strict depth rule made whole branches unfileable); the mount-time `boundaryHierarchyOrder` prefetch is removed and derived from the same response the cascade renders; and for citizens the passed tenant now wins over the home-city override, which previously sent every lookup to the state root and produced `HIERARCHY_DEFINITION_DOES_NOT_EXIST`. (CCSD-1974)
- **Rate & Close screen** uses a Mozambique option set (`CS_FEEDBACK_EASY_SUBMIT` / `COMMUNICATION` / `RESOLUTION_TIME` / `OTHERS`), each with an English fallback so nothing renders a raw key before seeding. (CCSD-1961)
- **Employee login branding de-hardcoded.** `V2LoginShell` is full-width with a transparent background so the StateInfo banner shows edge-to-edge; hardcoded hex colours become `var(--color-primary-main, #c84c0e)` tokens so the MDMS ThemeConfig actually drives brand colours. When `CS_LOGIN_PORTAL_TITLE` is seeded, the emblem + two-line portal branding replaces the legacy header — **other deployments render byte-identical output**. (CCSD-1995, CCSD-2060, CCSD-1977)
- **`allowed.source` extended** to `whatsapp,web,mobile,RB Bot,email,inperson,letter,linhaverde` so the reception officer's channel of receipt rides the standard `service.source` field rather than an `extendedAttributes` row.
- **Registry corrections in the Studio:** the `StateInfo` master is relabelled "Branding" (it was showing an internal name), and `decryption-abac`'s `idField`/`nameField` are corrected to `key` — the schema's actual identifier — so the list shows a name and the key is correctly immutable in edit. (CCSD-1997, CCSD-1999)

### Functionality removed/disabled

- **Auto-escalation removed from the CMS workflow.** `CmsPgrWorkflowConfig.json` contains no `ESCALATE`/auto-forward actions and neither `PENDINGATSUPERVISOR` nor `RESOLVEDBYSUPERVISOR`; the roles `AUTO_ESCALATE`, `SYSTEM`, `SUPERVISOR` and `PGR_LME` appear nowhere in it. Mozambique escalates through an explicit human supervisor tier — expressed as the `REFERRED → REASSIGN → PENDINGFORREASSIGNMENT` loop back to the screening officer — not through a timer. **The standard workflow retains auto-escalation; only the CMS variant drops it.**
- **Citizen free-text participation narrowed.** In the CMS workflow, `CITIZEN COMMENT` survives only on `REJECTED` and `RESOLVED`. The `INFOFROMCITIZEN` state has exactly one action — `COMMENT → INVESTIGATION` — granted to `CMS_CASE_MANAGER` and `CMS_RECEPTION_OFFICER` and **not** to CITIZEN, so staff record the citizen's answer (matching a counter / green-line intake model in which many complainants are not online). CITIZEN appears on 7 of 18 CMS actions.
- **HRMS jurisdiction pruning of the boundary picker disabled.** `allowedRoots` is hardcoded to `null` in `BoundaryComponent`, so employees see the same full tree citizens do. Reception officers take complaints for the whole country, and the upstream pruning collapsed the picker to a single province. **The prune machinery is kept dormant rather than deleted, so it can be re-enabled.**
- **"All Services" citizen hub removed.** CCRS exposes exactly one citizen module, so the page held a single card and the sidebar showed two rows pointing at the same destination. `/citizen/all-services` now redirects to the sole module's configured `sidebarURL`, derived from the same MDMS rows the sidebar renders — multi-module tenants are untouched. The two citizen rows in the action catalog are repointed to `/digit-ui/citizen/pgr-home`. (CCSD-2126)
- **Postal-code auto-fill from the map pin removed** from the citizen wizard: foreign postal formats failed the inherited validation and blocked the NEXT button outright.
- **`default-data-handler` removed from the local compose stack** (31-line service block deleted). See *Breaking changes* and Known Limitations #7.
- **`seed-testing-tenant.py` abandoned.** A 317-line deploy-time tenant-cloning seeder was added and then deleted in the same release line, replaced by the Configurator's `isTestingTenant` flag; the testing tenant is now onboarded through the normal tooling.
- **Vendored `::-webkit-media-controls-panel` CSS rule deleted** from `packages/css/src/components/topbar.scss` — it pinned video controls at `top: 55%` and was the root cause of broken media controls.

### Bug fixes

- **Create-complaint submit crashed the page on current Chrome.** `TextInput` passed a compiled `RegExp` straight to the DOM `pattern` attribute; a `RegExp` stringifies to `/source/u`, which older Chrome silently ignored but Chrome 150+ compiles with the v-flag and throws on form submit, bouncing the operator to the employee language-selection screen. `asPatternAttr()` now unwraps the RegExp to its `.source` on both render paths.
  `digit-ui-esbuild/packages/react-components/src/atoms/TextInput.js`
- **Rating notifications greeted the wrong officer** ("Prezado(a) Supervisor" on a notification that should address the Case Manager). `getEmployeeName` overwrote its result on every match while `/process/_search` returns history newest-first, so the **oldest** matching step won. The loop now tracks `auditDetails.lastModifiedTime` and keeps the newest. (CCSD-2167)
- **Workflow history fetch was a silent no-op.** `WorkflowService.getByBusinessId` referenced `Urls.WorkFlowProcessSearch`, a key that never existed in the module's `urls.js`, and `Urls.workflow.processSearch` lacked a leading slash. Both fixed.
- **`AWAITINGINFORMATION` transition failed with "Documents cannot be null for status: INFOFROMCITIZEN"** even after the frontend made the field optional, because `egov-workflow-v2` gates transitions *into* the state. `docUploadRequired` flipped to `false` on `INFOFROMCITIZEN`, which fixes both layers (the frontend also reads the flag to derive `isMandatory`). (CCSD-2081)
- **Employee-created complaints had no coordinates.** `address.geoLocation` was hardcoded to `{}`, so the map pin was silently discarded and the details map never rendered. Real `{latitude, longitude}` is now emitted when a pin exists (still `{}` otherwise, for the persister). (CCSD-2131)
- **Infinite reverse-geocode request loop.** The formData sync effect re-fetched on the write produced by its own failed geocode; a single `geocodeAttemptRef` now guards one attempt per unique coordinate. The geocoder is also restricted by country code, and geolocation errors surface as timed toasts. (CCSD-1993)
- **Citizen details page crashed** because `TimelineWrapper` read `useMyContext`, which does not exist on the citizen route tree; the dependency was removed.
- **Ward tooltip HTML is now escaped** against injection, and the opaque permanent Leaflet tooltip that covered the pin was replaced by a shared translucent panel on both the picker and the details map.
- **Login/OTP/forgot-password rendered raw ALL-CAPS keys.** Those screens pre-translated their text with `t()` and then re-ran the result through a `tr(key, fallback)` helper (a double resolve). Raw keys now pass through and resolve once, with guards including the composed `<key> <number>` OTP shape.
- **Portuguese names were rejected by profile validation.** The name pattern now admits accented Latin ranges (`A-ÖØ-öø-ÿ`), so "Manhiça" and "Conceição" pass; e-mail uses the same strict pattern as the complaint form; `TRANSGENDER` is filtered client-side so the change holds regardless of per-environment seeding. (CCSD-1988/1989/1990/1991/1992)
- **Studio localization edits appeared to do nothing.** A corrected Portuguese string did not reach the rendered UI until re-login or a 24h TTL lapse. `useLocalizationSaveRefresh` now clears all three caches on save — server-side cache-bust POST, frontend memory + localStorage, then re-set the active locale to force an i18n re-fetch — wired to both create and a new `DigitEdit.afterUpdate` hook. `LocalizationCreate`'s default module corrected from `rainmaker-common` to `configurator-ui`. (CCSD-2157)
- **Studio rendered blank on a non-English boot locale.** The sync path in `getMessages` now covers the *resolved* locale; without it `ra-i18n-polyglot` throws "returned a Promise for the messages of the default locale". `resolveInitialLocale()` maps `LOCALE_DEFAULT`/`LOCALE_REGION` onto available locales (exact match, then language prefix — portal `pt_PT` → studio `pt_BR`, else `en_IN`), and a user's stored manual pick still wins.
- **Banner image could not be saved on pre-existing city-module rows.** The generic Edit form derives inputs from the keys the *record* already carries, so rows created before the schema gained `bannerImage` could never be given one; the `city-module` descriptor now declares the fields explicitly. (CCSD-1959)
- **Employee dashboard was a dead end** with content flush against the left rail and viewport edge; a breadcrumb rendered only when embedded (so `<Link>` never mounts outside the host Router) plus gutter/vertical-rhythm restoration. Labels are `exists()`-guarded with English fallbacks because the dashboard's `t()` echoes the key when unseeded.

### Infrastructure & deployment changes

Deployment model (unchanged from upstream): single-host **Docker Compose driven by Ansible** — `local-setup/ansible/deploy.sh <tenant>` → `playbook-deploy.yml` → `local-setup/docker-compose.egov-digit.yaml` (+ migrations, monitoring and fast-path overlays), fronted by Kong, health-checked by Gatus.

The Mozambique infra delta is small and surgical: **15 files, +549 / −9 across 19 non-merge commits, all inside `local-setup/`.**

- **`docs/migration/ccrs-migrate.cjs` — the unified migration runner** (1,212 lines, zero npm dependencies, Node ≥ 14). One re-runnable command replacing six ad-hoc scripts whose failure modes and auth conventions disagreed. Nine phases: `auth, schemas, hierarchy, pgr-masters, landing, cms, banner, gzip, verify`. Each phase is isolated — a failure records a **stable error code plus remediation text and the run continues**; a summary table prints every phase and the exit code is the number of phases needing attention. Flags: `--dry-run`, `--phases`, `--only`, `--report out.json`, `--tenant` as a comma list sharing one state root, `--update-masters`, `--banner-url`. `OAUTH_BASIC` is accepted plaintext or base64; a 45s HTTP timeout applies.
- **Never-overwrite seeding policy.** Operators customise landing text and banners through the Studio, and a migration re-run must not reset that work. Localization upserts are **add-if-missing** (existing codes are searched first and reported as "all N keys present — kept untouched"); masters compute a drift set and by default only **warn**, with writes gated behind `--update-masters`; banner rows are create-missing-only and an operator-chosen banner can only be replaced with `--banner-url` **and** `--update-masters`.
- **Environment quirks encoded as executable workarounds** rather than tribal knowledge, each with a comment naming the incident: async schema persistence (202 + verify-after, `SCHEMA_NOT_PERSISTED` with a DB-insert hint); the MDMS v2 `x-ref-schema [] → {}` coercion bug (stripped before create, with the exact repairing SQL printed on a hit); non-ASCII schema descriptions silently dropped (sanitised to printable ASCII, capped at 500 chars); a 400 "extraneous key [tenantId]" retried once with `tenantId` stripped; **one-locale-per-call** localization upserts (mixed-locale batches are silently dropped); schema search silently paging at 10 unless an explicit limit is passed; MDMS having **no schema-update API at all**; and `egov-workflow-v2` caching BusinessServices so a newly created workflow needs a service restart.
- **gzip + `Cache-Control: no-cache` on the `/digit-ui` bundle.** The SPA ships as a single non-code-split ~7–8 MB `index.js` plus ~1.5 MB CSS, previously served uncompressed with no cache header; every cold load on a Mozambican mobile connection pulled it raw. **Measured locally 7.2 MB → 2.1 MB.** The identical block (`gzip on`, `gzip_vary on`, `gzip_min_length 1024`, `gzip_comp_level 5`, `gzip_types …`) is added in all three render paths — the static-mode host vhost template, the container-mode `digit-ui.conf`, and the config the playbook writes inline — and is deliberately **scoped to the `/digit-ui` location**, so the Kong-proxied `location /` is byte-identical to before. Backed by a runbook (`docs/ops/digit-ui-compression.md`), a runner phase and a guided `enable-gzip.sh`. The runner's `gzip` phase probes with `Accept-Encoding` (so it doubles as a remote post-deploy check) and, when run on the serving box, auto-discovers the config that actually serves `/digit-ui`, skipping `return 30x` redirect stubs and refusing backup/`.bak` files. **See Known Limitations — the documented `--tags nginx` shortcut is currently a no-op.**
- **Password-gated `/digit-ui-test` testing entrance (default OFF).** Mozambique has no separate staging server and runs QA against live pilot/production boxes, so a gated same-box entrance isolates test data. `group_vars/digit.yml` adds `testing_ui_enabled: false` plus documented opt-in keys (`testing_tenant`, `testing_ui_htpasswd`, `testing_ui_path`, `testing_ui_banner`). When a host opts in, the playbook renders a second `globalConfigs` (context path `digit-ui-test`, `TESTING_MODE=true`, login allowlist narrowed to the testing tenant), writes `.htpasswd-testing` (mode 0640, task marked `no_log`) from a **pre-hashed** htpasswd line, and adds nginx locations with `auth_basic` plus a `sub_filter`-injected red "TESTING ENVIRONMENT — data created here is not real" banner. **Every added block is Jinja-gated, so a box that does not opt in renders byte-identical nginx config and `globalConfigs.js` and gains no new files.** The repository contains only placeholder text — the credential is an example/test default that MUST be changed and should live in vault, not plain `host_vars`. Runbook: `local-setup/ansible/docs/testing-entrance.md` (159 lines).
- **`local-setup/scripts/deploy-pilot-fe.sh`** (177 lines) — one-shot pilot/production frontend build + deploy, replacing a hand-run multi-step runbook (checkout, `npm ci`, esbuild build against the server's `globalConfigs.js`, tar into the digit-ui container, vendored configurator build, rsync to the docroot). Usage `deploy-pilot-fe.sh [all|ui|configurator] [branch] [--no-pull]`. Enforces a Node ≥ 20 floor with auto-selection from `$NODE20_BIN` or the newest nvm v2x install, and skips `npm ci` unless `package-lock.json`'s checksum changed.
- **Filestore MIME allowlist extended** with `mp4`, `mov`, `avi`, `mkv`, `webm` and `pptx` — applied consistently to **all five compose variants and the k8s manifest**, so every serving mode agrees. Without this, `egov-filestore` rejected the video evidence citizens attach. (CCSD-2027)
- **pt_PT / PT set as the container-mode default locale** in `local-setup/nginx/globalConfigs.js`. Note the Ansible template already parameterises `locale_region`/`locale_default`, so Ansible-managed hosts take their locale from `host_vars`, not from this file.
- **Postgres base image** for the `db/normalize` build moved off `registry.preview.egov.theflywheel.in` to `egovio/postgres:16`, consolidating on the public namespace used by every other image. Still an `ARG`, so it remains overridable at build time.
- **Operator documentation set:** `docs/migration/README.md` (recommended entry point, phase→legacy-script mapping, environment-quirk list), `docs/migration/seed/README.md`, `docs/migration/seed/pgr-dynamic-fields-masters-onboarding.md` (zero-experience local + production runbook), `docs/ops/digit-ui-compression.md`, `local-setup/ansible/docs/testing-entrance.md`.
- **New in the v1.0.0 commit itself:** `.github/CODEOWNERS` (+3 lines) and `local-setup/ansible/inventory/host_vars/stateige.yml.example` (+290 lines) — an Ansible host_vars example for the IGE state deployment. All credentials in it are **example/test defaults that MUST be changed** before any real use.

#### Post-deployment configuration (required)

- **`node docs/migration/ccrs-migrate.cjs --only cms` is a MANUAL post-deploy step** in this release — deploy-time CMS seeding is not included (see Known Limitations #3). It registers CMS roles at **both** the state root and the city tenant (MDMS v1 role lookups do not overlay state rows onto a city here, and the Configurator's employee-upload validator only reads city rows), actions and grants at the state, and the CMS PGR BusinessService at the city. **`egov-workflow-v2` caches BusinessServices and must be restarted after a workflow create.**
- **Narrowing the authority list is an environment task, not a product change.** The product seed `docs/migration/seed/ComplaintRelatedToMap.json` ships **both** authorities active (`IGE → mz.ige`, `IGSAE → mz.igsae`). For an IGE-only launch the operator narrows the environment *after* deployment so exactly one row is active; the citizen flow then auto-selects it and hides the authority picker.
  **Discrepancy to be aware of:** the live `cms-pilot` environment has exactly one row — `IGE`, `tenantCode = mz`, `active = true` — while the shipped seed maps `IGE → mz.ige`. **Which mapping is intended is NOT VERIFIED.** Both are documented here deliberately; do not silently "correct" either without a decision.

### Database changes

- **There are ZERO Mozambique-specific database migrations.** `git diff --name-only 815b2374...master -- '*.sql'` returns nothing; **all 22 Flyway migrations are byte-identical to upstream.**
- **Consequences.** No Mozambique-specific migration is required for a fresh install or an upgrade, and **nothing in this release blocks an image rollback** on migration grounds (upstream policy, `docs/rapid-release-approach.md` §6: image rollback is safe only when migrations are backward-compatible).
- **All Mozambique state lives in MDMS, localization and workflow master data**, applied through `docs/migration/ccrs-migrate.cjs` — not through schema migrations.
- **One operator script writes directly to the database.** `docs/migration/fix-citymodule.sh` (106 lines) exists because **MDMS has no schema-update API**: on environments whose `tenant.citymodule` schema predates the `bannerImage` property, the value cannot be stored at all. Run **on the box**, it locates the postgres container that actually owns `eg_mdms_schema_definition` (a box may run several — MCP, Keycloak, DIGIT), patches the schema definition via SQL when the property is missing, restarts MDMS **only if something changed**, re-creates missing Workbench/PGR/HRMS rows through the API, and verifies through the same APIs the UI uses. **Existing rows are never touched.** The runner's `banner` phase performs the API-doable half and reports `CITYMODULE_SCHEMA_DRIFT` with this script as the remediation.

#### Gaps found in the data layer (not fixed by this release)

- **No down-migrations or undo scripts exist anywhere in the repository.** Rollback of a schema change means restoring the database from a dump.
- **The MDMS seeding layer has no version table, no checksum and no applied-state record.** Idempotency is achieved by search-before-write inside the runner, not by tracked state; there is no way to ask an environment "which seed version are you on?".
- **A newly created workflow BusinessService requires an `egov-workflow-v2` restart** — the service caches BusinessServices. This is called out in the runner's output and in the runbooks.
- **Two migrations end with a NON-CONCURRENT `REFRESH MATERIALIZED VIEW`.** Their duration on production-sized data is **unmeasured**; a non-concurrent refresh takes an `ACCESS EXCLUSIVE` lock. Measure before running against production.

### Breaking changes

Relative to an upstream CCRS deployment. Nothing here breaks *within* an existing Mozambique environment already running this line.

1. **`PGR_WORKFLOW_VARIANT` is no longer set anywhere in the tree.** `git grep PGR_WORKFLOW_VARIANT` at the release commit returns **zero hits**. The Java side survives (`DataHandlerService` still reads `@Value("${pgr.workflow.variant:standard}")` and selects `CmsPgrWorkflowConfig.json` when the value is `cms`), but nothing sets it, so the effective default is `standard`. The CMS multi-tier workflow now reaches a tenant **only** through a manual `ccrs-migrate --only cms` run. **NEEDS VERIFICATION on each target environment before go-live.**
2. **`default-data-handler` was removed from the local compose stack.** Tenant-creation-time seeding (workflow, roles, localization packs) no longer happens automatically in that stack; it must be driven by the migration runner.
3. **Workflow state vocabulary changes for CMS-seeded tenants.** `PENDINGATLME`, `PENDINGATSUPERVISOR` and `RESOLVEDBYSUPERVISOR` do not exist in the CMS workflow; `REFERRED`, `INVESTIGATION` and `INFOFROMCITIZEN` replace them. Any report, dashboard filter, integration or alert keyed on the old state names will silently return nothing on a CMS tenant. Auto-escalation actions are likewise absent.
4. **Confidential-complaint response shape changes.** Fields listed in a template's `x-no-mask` array now return **real values** on `/request/_search`, `/_plainsearch` and `/request/_update` where they previously returned the `****` sentinel. Any consumer treating `****` as invariant for confidential complaints must be reviewed.
5. **`service.extendedAttributes` is a new top-level field** on `/pgr-services/v2/request/_create` (additive, but persisters/indexers/consumers that assume the previous payload shape should be checked). The citizen flow no longer sends a bare `additionalDetail: "{}"`.
6. **Search result sets narrow for configured roles** once `pgr.department.scope.roles` is populated. Shipped empty, so this is a no-op on upgrade — but it is a behavioural break the moment an operator opts in, and it **fails closed**: an HRMS outage returns zero results, not everything.
7. **Privacy-policy master relocated** from `commonUiConfig.PrivacyPolicy` to `commonMDMSConfig.PrivacyPolicy` (schema code change). Anything reading the old path will find nothing.
8. **Citizen navigation:** `/citizen/all-services` no longer renders a page; it redirects to the sole module's home. Bookmarks and deep links to the hub resolve elsewhere.
9. **Employee boundary visibility widens.** With HRMS jurisdiction pruning disabled, every employee sees the full boundary tree rather than their assigned jurisdictions. Deliberate for Mozambique's operating model; a security-relevant change for anyone reusing this tree.

### Known limitations

Ordered by severity. All of these are **present in `cms-mozambique-v1.0.0` and not fixed by it** — this is a documentation-only release.

1. **SECURITY — `POST /pgr-services/v2/request/_admin/_search` has no authorization gate.**
   - `AdminComplaintSearchController` performs **no role check**; its javadoc claims gateway-level gating **that does not exist**.
   - **No `ACCESSCONTROL` action is registered for the URI** (0 hits in both action masters), there is no `@PreAuthorize`, and there is **no Kong route entry** for it.
   - `AdminComplaintSearchService` validates only `tenantId` and sets `skipEmployeeDepartmentScope(true)`, **deliberately bypassing department ABAC**. Its two mentions of "SUPERUSER" are **comments**, not enforcement.
   - **Proven on the `cms-pilot` environment:** a user holding only `CMS_SCREENING_OFFICER` + `EMPLOYEE` received **HTTP 200 with complaint rows**.
   - The only gate is client-side — `ADMIN_SEARCH_ROLES` in `digit-ui-esbuild/products/pgr/src/pages/employee/AdminSearch.js` — and is bypassed by calling the API directly.
   - **Recommended fix:** enforce the role in the service/controller, or register the action and the corresponding roleactions grant. Until then, treat network reachability of this URI as the only control.
2. **No automated test coverage for the Mozambique feature set.** Across all 556 commits: **1 test added and 2 modified** — added `configurator/src/providers/resolveInitialLocale.test.ts`; modified `backend/pgr-services/.../PGRServiceCountScopingTest.java` and `configurator/.../dataProvider.test.ts`. There is **no automated coverage for workflow transitions, notifications, extended attributes, roles/permissions or localization**. This is the single largest release-readiness gap.
3. **Only 5 of the 7 seeded `CMS_*` roles are auto-registered.** This release's `docs/migration/ccrs-migrate.cjs` registers `CMS_RECEPTION_OFFICER`, `CMS_SCREENING_OFFICER`, `CMS_SUPERVISOR`, `CMS_CASE_MANAGER` and `CMS_VIEWER`. **`CMS_ADMIN`, `CMS_DASHBOARD_VIEWER` and `CONFIDENTIAL_COMPLAINT_VIEWER` are NOT auto-registered**, even though features requiring them *are* in the release. **They must be registered manually.**
4. **Deploy-time CMS seeding is not in this release** — `node docs/migration/ccrs-migrate.cjs --only cms` is a **manual post-deploy step**.
5. **The CCSD-2171 geography drill-down is not in this release** (analytics `boundaryPath` subtree parameter + dashboard geography drill-down filter).
6. **`CMS_VIEWER` is a "viewer"-named role with full write authority.** It appears on 12 of the 18 CMS workflow actions — every `ASSIGN`, `REJECT`, `REASSIGN`, `RESOLVE`, `AWAITINGINFORMATION` and both `REOPEN`s — and holds a grant set byte-identical to GRO's 37 actions, including `/egov-wf/process/_transition`, PGR `_create`/`_update` and localization `_create`/`_update`. The name misleads; treat it as an oversight/superset role and assign accordingly.
7. **DEFECT — `CENTRAL_USER` and `DEPARTMENT_USER` grants are hardcoded to `tenantId: "pb"`.** 44 of the 731 roleactions rows (all 22 `CENTRAL_USER` + all 22 `DEPARTMENT_USER`) carry the DIGIT India sample state instead of the `{tenantid}` placeholder (they also omit the `id` field every other row carries). Because substitution is a literal string replace, these grants are created under tenant `pb`, so **on any Mozambique tenant these two scope roles end up with zero grants**.
8. **GAP — notification routing was never extended to the CMS states.** `NotificationRouter.route()` matches on `(businessService, action, toState)`; the CMS target states `REFERRED`, `INVESTIGATION`, `INFOFROMCITIZEN` and `CLOSEDAFTERREJECTION` have **no routing row**. Consequently both `ASSIGN` hops, `AWAITINGINFORMATION`, `REJECTED.REOPEN` and rate-after-rejection have no matching default routing. The notification routing file is byte-identical to upstream.
9. **DEFECT — `PENDINGFORREASSIGNMENT` reports `applicationStatus: "REASSIGND"`** (misspelt, and the only state in either workflow file where status ≠ state name). Backend code already compensates — `WorkflowService.isTargetStateTerminal()` matches on `applicationStatus` **or** state name, and its javadoc calls the quirk out — but **no localization key `CS_COMMON_REASSIGND` / `CS_COMMON_PGR_STATE_REASSIGND` exists in either the `en_IN` or `pt_PT` seeds**, while `CS_COMMON_PGR_STATE_PENDINGFORREASSIGNMENT` is seeded in both.
10. **Portuguese coverage is partial.** All 114 `PGR_LANDING_*` keys are translated, but **1,101 `en_IN` `rainmaker-pgr` keys still have no `pt_PT` row** — including all 22 `CS_ACTION_*` labels. Unseeded keys fall back to English (the code paths guard against rendering the raw key), but the UI is mixed-language in places.
11. **REGRESSION — the `nginx` Ansible tag is missing at the release commit.** `docs/ops/digit-ui-compression.md` documents `./deploy.sh <host> --tags nginx` as the surgical way to re-render the host nginx config and fire the reload handler. Commit `78436401` added `tags: ['nginx']` to the four host-nginx tasks precisely to make that command real, but **the tags were lost in a later merge from master** — the only remaining `tags:` entries in the playbook are `['mcp-publish','never']` and `['notifications','notification-seed']`. The documented command now reports `ok=0 changed=0` and **touches nothing**. Use a full playbook run, or the `enable-gzip.sh` / runner `gzip` phase, until the tags are restored.
12. **`stateige.yml.example` carries a stale header.** The file added by the release commit still shows the `bomet.yml.example` header ("deploy.sh bomet") and sets `domain: localhost`. Misleading for an operator copying it as a starting point; all credentials in it are example/test defaults that MUST be changed.
13. **The `develop` branch has diverged from `master`** (2 ahead / 1 behind) but **their trees are identical** — pure history duplication of `stateige.yml.example`. Technical debt, not a release blocker.
14. **Documentation drift.** Several design documents in the delta no longer match what shipped, and should be read as historical intent rather than specification:
    - `docs/complaint-search-page.md` (Draft, 2026-06-21) is contradicted on nearly every load-bearing point by the shipped `AdminSearch.js`.
    - `docs/agency-category-tenant-mapping.md` specifies an MDMS master `RAINMAKER-PGR.AuthorityConfig` that **was never built** — the shipped mechanism is `ComplaintRelatedToMap`.
    - `docs/complaint-hierarchy-withnew-parameters.md` records a decision record ("Do NOT introduce hierarchical masters") that the shipped N-level hierarchy contradicts.
    - `docs/superpowers/specs/mozambique-prd/2026-06-22-mozambique-prd-solution-design.md` (the anchor architecture spec) is **partly superseded**.
    - `docs/SAAS_Standalone_Tenant_Design.md` is **partially realised**.
    - `docs/README.md` was added and then never updated for the tooling that replaced its contents.
    - `docs/migration/seed/README.md` contains two concrete errors: a link to `../citizen-authority-tenant-integration-plan.md`, which **does not exist** at this commit, and a wrong `UID_KEY`.
    - `docs/category-details-dynamic-fields.md` (1,349 lines) is the one large design document that **does** match the code — every path it claims exists.
